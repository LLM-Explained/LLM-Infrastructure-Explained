# PagedWeight: Dynamic Quality-Aware MoE Quantization Miniature

This CPU-only demo reproduces the **planning principle** behind PagedWeight: treat routed-expert precision as a runtime memory resource, lower the precision of the least damaging expert blocks when KV-cache pressure rises, and restore valuable pages when headroom returns.

The real PagedWeight system uses an Any-Precision bit-plane representation, CPU/GPU weight paging, calibrated quality signals, asynchronous movement, safe page-table commits, and fused mixed-precision MoE kernels. This miniature deliberately isolates the policy layer so the central trade-off can be inspected without proprietary traces, model weights, or a GPU.

## Core idea

For every legal precision transition, such as `16 -> 8` or `8 -> 4`, the planner estimates:

```text
predicted quality damage / bytes released
```

The synthetic damage proxy combines:

- offline block sensitivity;
- recent expert-routing mass;
- a prompt-conditioned residual signal;
- the severity of the precision reduction.

The quality-aware planner repeatedly selects the lowest-damage transition until it has released enough memory for the requested KV-cache growth. The baseline instead lowers every eligible block in lockstep, approximating a static uniform-bit policy.

## Expected result

For six equal-size synthetic expert blocks, KV-cache pressure requests 72 MiB of additional space:

```text
initial expert memory: 192.0 MiB
KV-cache pressure asks for: 72.0 MiB

Quality-aware plan:
  released memory: 84.0 MiB
  predicted damage: 1.2231

Uniform baseline:
  released memory: 96.0 MiB
  predicted damage: 3.5050

predicted-damage reduction: 65.1%
hot expert remains at: 16 bit
```

When 48 MiB of headroom later becomes available, the restoration policy raises the precision of the pages with the greatest avoided damage per added byte.

These values are generated by a transparent synthetic model. They are **not** reproductions of the paper's measured accuracy, memory, or throughput results.

## Baseline and ablations

- `quality_aware_plan`: greedy prompt- and routing-aware selection by predicted damage per released byte.
- `uniform_plan`: lowers all eligible blocks one level in lockstep.
- `restore_with_headroom`: reverses transitions according to avoided damage per added byte.
- Per-block precision floors protect sensitive experts from unsafe reductions.

## What this validates

The demo validates that:

- expert blocks can be modeled as independently resizable memory pages;
- routing and prompt signals can change which blocks should be compressed first;
- a quality-aware policy can meet a memory target with lower predicted damage than a uniform policy;
- sensitive or frequently routed blocks can remain at higher precision;
- precision can be restored when memory pressure falls;
- deterministic validation can cover target satisfaction, precision floors, policy ordering, baseline comparison, and restoration.

## What this does not validate

It does not reproduce:

- the paper's Any-Precision bit-plane storage format;
- real quantization error or downstream model quality;
- Hessian/sensitivity calibration from model activations;
- GPU/CPU paging, DMA overlap, or transactional page commits;
- fused mixed-precision MoE GEMM kernels;
- vLLM integration, scheduling, or KV-cache allocation;
- RTX 6000 Ada or GH200 benchmark results;
- the reported 72% memory saving, 1.94x throughput gain, or 39.3% quality improvement.
